# CLAUDE.md

MkDocs (Material) site. The textbook "EE pre SŠ" lives in `docs/` and is written in **Slovak**.
This file is in English. It is also the working plan for converting the scanned notes into chapter content.

## How to resume (read first)

1. Read the "Task list" below and find the first unticked `[ ]` task.
2. Do only that one task, then tick it `[x]` and add a one-line note if something was decided.

## Decisions (agreed with the user)

- **Math:** `pymdownx.arithmatex` (generic mode) + MathJax 3, written as `$...$` and `$$...$$`.
- **Diagrams:** SVG authored by Claude from the scan, stored in `docs/svg/<chapter>_<topic>.svg`. Either written by hand or generated by a small stdlib-only Python script (useful for exact curves); no external toolchain. A generator script is archived in `tools/diagrams/` (see practice 4).
- **Text depth:** faithful transcription of the notes (headings, LaTeX, SVG) plus at most one short connecting sentence in Slovak between steps. The user expands the prose later.
- **Language:** all site content in Slovak. Keep the user's terminology (DPF/HPF, "prenosová funkcia", "fázor").
- The original scans in `docs/scan/` stay in the repo, but the chapters do not reference them: when a scan is converted, its `![](scan/...)` line is replaced by the converted content. Do not delete scan files. Unconverted chapters keep their scan references and the scans stay on the built site, so those pages work as before. `mkdocs.yml` has an `exclude_docs` list: when a scan is converted, add its filename there (one `scan/<file>` per line) so it is no longer built into the site. A scan used by two chapters (`Trojfaz_1faz_tr.png`, `Trojfaz_usmer.png`) is added only after both chapters are converted. Currently excluded: `Filtre_RC.png`, `Filtre_RL.png`.

## Working practices (agreed with the user, apply throughout the project)

1. **Follow the scans closely.** The redundancy in the notes is on purpose: it supports incremental understanding for students. Keep each scan's structure, order and repetition (e.g. a separate figure and derivation for every filter, even when two are mathematically the same). Do not merge, shorten or reorder on your own.
2. **Suggestions go in `suggestions.md`**, afterwards. If you see a possible simplification or unification, finish the faithful version first, then add an entry to `suggestions.md` (repo root, not published). Never apply a suggestion without the user's approval.
3. **Exact values in labels and text:** use the original exact expressions (`1/√2`, `π/4`), not decimals (`0,707`).
4. **Archive generator scripts.** Any script used to produce a diagram is saved in `tools/diagrams/` (one script per chapter, named `gen_<Chapter>.py`, with usage in its docstring, default output `docs/svg/`), so figures can be regenerated and revisited. Hand-edits to a generated SVG must also be written back into its script (or the script's docstring must say the SVG was edited by hand afterwards).

## Conventions

- **Chapter files:** `docs/<Chapter>.md`. Keep the existing `##`/`###` skeleton and fill it in. Do not rename files or reorder `nav` without asking.
- **Math:** variables as in the notes: phasors `\underline{U}` or `\mathcal{U}` (match the scan), transfer function `\mathcal{H}(\omega)`, imaginary unit `\mathrm{j}`. Pick the notation once, record it in "Notation" below, and reuse it everywhere.
- **SVG:** follow "SVG style" below exactly. `viewBox` only (no fixed width/height), explicit colours (not `currentColor`: it does not inherit inside an `<img>`, and the site has a single light palette), same line weights across all files. Embed with `![popis](svg/xyz.svg){ width="500" }`.
- **Alt text** is in Slovak and describes what the figure shows.
- **Verification:** after each task, build into the scratchpad dir (not `site/`) with `/opt/miniconda3/bin/python -m mkdocs build -d <scratch>/site` and check the page's HTML. Do not use `--strict`: it always aborts on the `encryptcontent` brute-force warning. Read the other warnings by hand. The `mkdocs` on PATH does not work (see T0.3). Where possible, view the rendered SVG next to the scan before ticking the task.
- **Unclear handwriting:** never guess. Put a `<!-- TODO(scan): ... -->` comment in the Markdown and list it in the report.

## Notation (frozen at T0.6)

- Complex quantities (phasors, impedance, transfer function) in calligraphic letters, as in the handwritten notes: `\mathcal{U}`, `\mathcal{I}`, `\mathcal{Z}`, `\mathcal{H}`. Real magnitude and phase: `H(\omega)`, `\varphi(\omega)`. (Open question 4: calligraphic was chosen to match the scans, `\underline{U}` is the alternative.)
- Imaginary unit `\mathrm{j}`. Exponential `e^{\mathrm{j}\frac{\pi}{4}}`. Arctangent `\operatorname{arctg}`, as in Slovak textbooks.
- Exact values for corner points: `1/\sqrt{2}`, `\frac{\pi}{4}` (figures: `1/√2`, `π/4`), never decimals like 0,707. Where a decimal is unavoidable use the decimal comma (`0,5`), `{,}` inside LaTeX.
- Filter-type subscripts as plain letters: `\mathcal{H}_{DPF}`, `\mathcal{H}_{HPF}`. Terms: DPF/LPF dolnopriepustný, HPF hornopriepustný, AFCH amplitúdová frekvenčná charakteristika, FFCH fázová frekvenčná charakteristika, prenosová funkcia.
- Display equations with `$$` on their own lines, inline with `$`. Lists of cases ("tri význačné frekvencie") as Markdown bullet lists with inline math, not `cases`.
- Matrix-like alignment is not needed so far. Use `\underbrace` for naming parts of a formula as in the notes.

## SVG style (frozen at T0.6)

Why explicit colours: an SVG used through `![](x.svg)` is an `<img>`, so it cannot see the page's CSS or `currentColor`. The theme has no dark palette (`mkdocs.yml` has no `palette:`), so the figures are drawn for a light page. If a dark palette is added later, add one CSS filter rule for `img[src$=".svg"]` instead of editing every file.

**Canvas**
- `viewBox="0 0 W H"` with W = 600 for full-width figures (embedded with `width="650"` like the scans, or smaller), 300 for small ones. Transparent background. Everything on a 10-unit grid.
- Always include `<title>` (Slovak, same as the alt text).

**Colours**
| Role | Value |
|---|---|
| Lines, text, symbols | `#222` |
| Guides (dashed asymptotes, tick marks of reference values, construction lines) | `#888`, dasharray `5 4`, width 1 |
| Highlight (the curve or vector the notes mark in red) | `#c0392b`, width 2.5 |
| Second data series, if the notes use another colour | `#1f6fb2` |

**Strokes** (all `fill="none"`, `stroke-linecap="round"`, `stroke-linejoin="round"` on the root)
- Wires, component bodies: 2
- Axes: 1.5, with an arrowhead at the positive end
- Curves: 2
- Thin details (ticks, tick labels' leaders): 1

**Text**
- `font-family="'Helvetica Neue', Arial, sans-serif"`, `font-size` 16 for labels, 13 for tick values and secondary notes.
- Variables in italic, units and function names (`sin`, `H`, `arg`) upright, as in the book's formulas.
- Use Unicode for symbols: ω φ π Ω θ Δ ∞ ° √ ·. Subscripts with `<tspan baseline-shift="sub" font-size="70%">`. Do not use `<foreignObject>` or MathJax inside an SVG.
- Keep long derivations and equations in the Markdown (LaTeX). The SVG only carries short labels like `U`, `R`, `1/RC`, `ω`, `1/√2` (exact values, see practice 3).

**Symbols** (IEC style, as in the notes: the resistor is a rectangle)
- Resistor: rectangle 40×16. Capacitor: two parallel plates 24 long, 8 apart. Inductor: four semicircle bumps (coil). AC source: circle r=18 with a `~` inside. DC source: long and short line. Ground: three decreasing lines. Node: filled dot r=3. Wires are straight, horizontal or vertical, with 90° corners.
- Voltage arrow: a straight arrow beside the element, pointing to the + terminal, labelled next to its middle. Current arrow: on the wire, with its own head.

**Arrowheads** (put in `<defs>` of every file and use as `marker-end`)

```svg
<defs>
  <marker id="ar" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M0 1 L9 5 L0 9 z" fill="#222" stroke="none"/>
  </marker>
  <marker id="arr" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M0 1 L9 5 L0 9 z" fill="#c0392b" stroke="none"/>
  </marker>
</defs>
```

**Skeleton**

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 600 300"
     fill="none" stroke="#222" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"
     font-family="'Helvetica Neue', Arial, sans-serif" font-size="16">
  <title>Popis obrázka po slovensky</title>
  <defs>...</defs>
  ...
</svg>
```

**Text elements** must set `fill="#222" stroke="none"` (otherwise they inherit the stroke and look bold).

**Files:** `docs/svg/<Chapter>_<topic>.svg`, e.g. `Filtre_I_RC_obvod.svg`, `Filtre_I_bode_DPF.svg`. One file per diagram, not per scan page. A diagram used by two chapters is stored once and referenced by both.
